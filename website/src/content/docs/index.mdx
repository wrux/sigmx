## Everything htmx does, and what it leaves to you

<CardGrid>
  <Card title="Server-driven HTML" icon="rocket">
    Return plain HTML from any endpoint and `@get` or `@post` morphs it into the page by id. Return JSON to merge signals. Return an event stream when one request should keep delivering. Boosted links and forms, history, and `Last-Event-ID` reconnects are all in.
  </Card>
  <Card title="Signals, not sprinkles" icon="star">
    Client state lives in signals you declare in markup. `data-bind`, `data-show`, `data-class`, computed values and effects keep the page in step without a component model or a virtual DOM.
  </Card>
  <Card title="A morph that keeps your place" icon="approve-check">
    Patched HTML is merged, not replaced. Focus, typed input, scroll position and playing media survive every update because elements with ids are kept, wherever they move.
  </Card>
  <Card title="Pay for what you use" icon="setting">
    A 4 KB core and fifty-two opt-in plugins, including the Alpine and htmx extensions you would otherwise bolt on. Auto mode scans your source and bundles exactly what it finds.
  </Card>
</CardGrid>

## Why it is small

- No runtime dependencies, and a kernel written for gzip: a versioned reactive graph in 190 lines, a path-keyed store, and expressions that run as plain JavaScript.
- Plugins are values, not side effects, so bundlers drop what you do not register.
- Optional build-time compilation of expressions removes the compiler and `new Function` entirely.
- The numbers above are measured from the real source on every build, not quoted from memory.
