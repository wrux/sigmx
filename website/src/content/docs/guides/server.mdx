The functions `@get`, `@post`, `@put`, `@patch` and `@delete` send a request and apply the response. They need the `httpGet` … `httpDelete` plugins, plus `applyState` and `applyElements` to handle what comes back.

```html
<button data-on:click="@post('/cart/add', { payload: { sku: 42 } })">Add</button>
```

The simplest backend returns plain HTML. Render the fragment with whatever you already use, give its root element the same `id` as the one on the page, and send it with `Content-Type: text/html`:

```html
<!-- GET /cart → morphed over the existing <ul id="cart"> -->
<ul id="cart"><li>Kettle × 2</li></ul>
```

Streams and JSON are for when you need them, not a requirement.

## What is sent

- **Signals** as JSON: in the body for POST, PUT and PATCH; in the `sigmx` query parameter for GET and DELETE (a `contentType: 'form'` GET puts the form's fields in the query instead, and `readSignals` reads them back as signals, repeated names becoming arrays). Paths starting with `_` are left out. Change the set with `filter: { include, exclude }` or send something else with `payload`.
- **Headers** `Accept: text/event-stream, text/html, application/json` and `Sigmx-Request: true`, plus any you pass in `headers`.
- With `contentType: 'form'`, the closest form's fields instead of signals.

## What comes back

The response's content type decides what happens.

| content type | handling |
|---|---|
| `text/html` | patched as elements: morphed by `id`, or targeted by the `sigmx-selector` and `sigmx-mode` response headers (`append`, `inner`, `replace`, …) |
| `application/json` | merged as signals (`sigmx-only-if-missing: true` keeps existing values) |
| `text/event-stream` | each event is routed by name to a server-event handler; see below |
| `text/javascript` | executed |
| `204`, `304` | nothing |
| `4xx`, `5xx` | a `sigmx-fetch` event with `type: 'error'`; no retry unless `retry.onStatusError` |

## The event stream

An event stream lets one request apply many patches over time. Each event has a name and `key value` data lines:

```
event: sigmx-patch-signals
data: signals {"progress": 40}

event: sigmx-patch-elements
data: selector #job-log
data: mode append
data: elements <li>Validating…</li>

```

Two handlers ship with sigmx:

- **`patch-signals`**: `signals {json}`, optional `onlyIfMissing true`.
- **`patch-elements`**: `elements <html>` (repeat the line for multiline HTML), optional `selector`, `mode` (`outer` default, `inner`, `replace`, `prepend`, `append`, `before`, `after`, `remove`).

`id:` lines are remembered and sent back as `Last-Event-ID` on reconnect; `retry:` sets the reconnect delay. Every event also dispatches `sigmx-server-event` on `document`, so you can listen for custom events with `data-on:sigmx-server-event__document`.

Streams stay open while the tab is hidden. When a connection drops, the client reconnects with backoff and sends `Last-Event-ID`.

## Server helpers

Everything a server needs to speak the protocol ships in the core package as `sigmx/server`: plain Fetch-API code with no framework in it.

```ts
import {
  readSignals, validateSignals, isSigmxRequest,          // request side
  sse, sseStream, html, json,                            // responses
  patchElements, patchSignals, removeElements, removeSignals, executeScript,  // event builders
  SigmxStream, formatEvent, SSE_HEADERS,                 // lower level
} from 'sigmx/server'
```

Use it directly wherever handlers take a `Request` and return a `Response` (Hono, Bun, Deno, Cloudflare Workers, SvelteKit, Next route handlers). With Node's `http` or Express, `formatEvent` and `SSE_HEADERS` cover fixed responses and `Readable.fromWeb(sseStream(...).body)` pipes a live stream. The framework packages build on the same module: [`@sigmx/astro`](/sdks/astro/) re-exports it and [`@sigmx/hono`](/sdks/hono/) wraps it in middleware.

## Options

```ts
@post('/save', {
  headers: { 'X-Token': t },
  contentType: 'json' | 'form',
  selector: '#other-form',
  filter: { include: /^form\./ },
  payload: { anything: true },
  abort: 'replace' | 'none' | controller,   // 'replace' cancels an earlier request with the same method and URL
  reconnect: true,                          // reconnect after a stream closes normally
  retry: { attempts: 5, interval: 1000, factor: 2, max: 30000, onStatusError: false },
})
```

Requests are aborted when the element that started them is removed.

## Lifecycle events

`sigmx-fetch` fires on `document` with `detail.type` of `started`, `finished`, `error` or `retrying`, plus `el`, `method`, `url` and `status` or `attempt` where relevant. `data-indicator` is a convenience over it.

## Accepting another library's event names

Backends written for Datastar emit `datastar-patch-*` events. Accept them during a migration:

```ts
createSigmx({ plugins, eventPrefix: ['sigmx-', 'datastar-'] })
```
