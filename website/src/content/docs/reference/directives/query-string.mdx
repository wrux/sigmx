Sync signals with the URL query string, both ways.

## Syntax

```html
data-query-string:page="1"                  <!-- declare `page` with a default, synced with ?page= -->
data-query-string:sort-by="'name'"          <!-- parameter ?sort-by=, signal $sortBy -->
```

| part | |
|---|---|
| key | optional: a parameter name; the value is then the default |
| value | with a key, the default expression; without one, an optional `{ include, exclude }` filter |

## Modifiers

| modifier | effect |
|---|---|

## Example

<Live html={`
<div data-query-string:tab="'one'">
  <div class="row"><button data-on:click="$tab = 'one'">one</button><button data-on:click="$tab = 'two'">two</button></div>
  <p>tab = <b data-text="$tab"></b> (watch the address bar)</p>
</div>
`} />

## Notes

The keyed form is the usual one: it declares the signal, applies the default when the parameter is absent, and removes the parameter when the value equals the default, so URLs stay clean. Values that parse as JSON come back typed (`?page=2` gives the number 2). The bare form syncs signals declared elsewhere; give those defaults with `__ifmissing`.
