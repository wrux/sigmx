Send a request carrying your signals and apply the response.

## Syntax

```js
@get('/search')
@post('/save', { payload: { id: 3 } })
@post('/signup', { contentType: 'form' })
@delete('/items/' + $id)
```

Each function returns a promise that resolves when the response has been fully applied. Responses are handled by content type (event streams, HTML, JSON, JavaScript); see [Talking to the server](/guides/server/) for the protocol and all options.

| option | default | meaning |
|---|---|---|
| `headers` | | extra request headers |
| `contentType` | `'json'` | `'form'` serialises the closest form instead of signals |
| `selector` | | which form to serialise |
| `filter` | exclude paths starting with `_` | `{ include, exclude }` regular expressions over signal paths |
| `payload` | | send this instead of signals |
| `abort` | `'replace'` | `'replace'` cancels an earlier request with the same method and URL; `'none'` lets them overlap; or your own `AbortController` |
| `reconnect` | `false` | reconnect after a stream ends normally |
| `retry` | `{ attempts: 5, interval: 1000, factor: 2, max: 30000, onStatusError: false }` | backoff policy |

`@get` and `@delete` put the signals in the `sigmx` query parameter; the others send a JSON body. Requests are aborted when the element that started them leaves the document.
