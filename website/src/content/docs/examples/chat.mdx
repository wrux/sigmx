The message you type is posted with `@post`. The endpoint appends your bubble, appends an empty assistant bubble, then streams the reply **one word at a time by re-sending the whole paragraph** and letting the morph update it in place. Because each event carries the full text so far, a dropped or duplicated event changes nothing. Ask about the time or the weather to see a tool call: the server emits a custom `sigmx-tool` event and a handler registered on this page renders the card.

## What it uses

- `data-on:submit` with `@post('/api/chat')`, and `data-on:keydown` so Enter sends while Shift+Enter inserts a newline
- `patchElements` with `mode: append` for new bubbles, then `patchElements` by id for every streamed word
- `patchSignals` for `thinking`, the word counter and clearing the draft
- `data-indicator`, `data-attr:disabled`, `data-show` for the composer state
- a second endpoint, `/api/chat/stop`, that flips a flag the stream checks between words; the client identifies its conversation with a `chatId` set by `data-init`
- a custom server event (`event: sigmx-tool`) handled by a `handler()` plugin registered with `sigmx.use()`
- `data-scroll-into-view__smooth__vnearest` on every appended bubble
- `data-persist` so the unsent draft survives a reload

## Adapting it to a real model

Replace `think()` with a call to your model's streaming API and forward each token into the same loop. The client does not change: it only ever sees `patch-elements` events for one paragraph. If you want partial words to render as they arrive, send the accumulated text on every token; if you want to save bandwidth, batch tokens with a short timer.
